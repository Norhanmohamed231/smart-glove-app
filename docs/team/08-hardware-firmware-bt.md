# العضو 08 — Firmware والاتصال Bluetooth

| الحقل | القيمة |
|-------|--------|
| **العضو** | _[اكتب الاسم]_ |

| **الدور** | قائد محور الهاردوير — ESP32، OLED، Bluetooth، تنسيق الإرسال |

---

## المسؤولية باختصار

ملك **الكود الكامل للـ firmware**: الإقلاع، المعايرة، الحلقة الرئيسية 20Hz، `sendData()`، **BluetoothSerial** باسم `SignGlove`، وشاشة OLED. نقطة الاتصال الرئيسية مع التطبيق (العضو **02**).

---

## المخرجات الرئيسية

- [ ] Firmware مستقر يرسل CSV عند اتصال BT
- [ ] اسم الجهاز: `SignGlove`
- [ ] معدل 20 Hz (SAMPLE_RATE_MS = 50)
- [ ] OLED يعرض نسب flex و pitch/roll
- [ ] توثيق البروتوكول موقّع مع فريق Mobile

---

## الملفات / المكونات

| المكون | الوظيفة |
|--------|---------|
| `Gloves_Hardware_OLED.ino` (أو ما يعادله) | الملف الرئيسي |
| `sendData()` | تنسيق `DATA,...` + `\r\n` أو `\r` |
| `SerialBT.begin("SignGlove")` | Bluetooth Classic |
| `setup()` | معايرة MPU + Flex |
| `loop()` | عينة 20Hz + OLED 4Hz |

---

## عقد البيانات (إلزامي)

```text
DATA,<timestamp>,<f1>,<f2>,<f3>,<f4>,<f5>,<ax>,<ay>,<az>,<gx>,<gy>,<gz>,<pitch>,<roll>
```

- الإرسال على BT فقط عند `SerialBT.hasClient()`
- Flex: RAW (للتدريب والتطبيق)
- نهاية السطر: يجب الاتفاق مع **02** (`\r` مدعوم في التطبيق)

---

## الاعتماد على باقي الفريق

| يتنسق مع | لماذا |
|----------|--------|
| **06** | قراءات flex |
| **07** | قراءات IMU |
| **05** | تركيب فيزيائي |
| **02** | اختبار Parser على جهاز حقيقي |
| **10** | نفس التنسيق عند تسجيل dataset |

---

## ما يقدّمه في العرض

1. مخطط النظام المدمج (ESP32 + حساسات + BT + OLED).
2. تسلسل الإقلاع: معايرة → READY → بث.
3. شرح `sendData()` سطراً بسطر.
4. Demo: Serial/BT monitor لسطر واحد حي.
5. تحديات: توقيت 20Hz، استهلاك طاقة، استقرار BT.
